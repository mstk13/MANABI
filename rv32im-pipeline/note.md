# RV32IM 5段パイプライン CPU — 設計の全体像

自作 AI プロセッサ (DENNO) のホストコアを RTL 実装するための設計解説。
上位仕様: [DENNO/CPU/docs/実装仕様.md](https://github.com/mstk13/SHISAKU)

---

## 1. ISA: RV32IM とは

**ISA (Instruction Set Architecture)** = CPU が理解できる「命令の辞書」。

```
RV  32  I    M
│   │   │    └── M拡張: 乗算・除算 (MUL, DIV など 8命令)
│   │   └────── I: 基本整数命令セット (47命令)
│   └────────── 32: レジスタもアドレスも 32bit
└────────────── RISC-V
```

### レジスタ: CPU の中にある「引き出し」

CPU はメモリから直接計算しない。まず**レジスタ**（超高速な引き出し）にデータをコピーし、レジスタ同士で計算し、結果をメモリに戻す。

```
x0  = 常に 0 (書いても変わらない。「ゼロが欲しい」時に便利)
x1  = ra (return address — 関数の戻り先)
x2  = sp (stack pointer)
...
x31 = t6

全部で 32 本、各 32bit
```

### 命令の具体例

**ALU (計算) 命令**:
```
ADD  x3, x1, x2    # x3 = x1 + x2  (足し算)
SUB  x3, x1, x2    # x3 = x1 - x2  (引き算)
ADDI x3, x1, 10    # x3 = x1 + 10  (即値を足す)
AND  x3, x1, x2    # x3 = x1 & x2  (ビットAND)
SLT  x3, x1, x2    # x3 = (x1 < x2) ? 1 : 0  (比較)
```

**Load/Store (メモリアクセス) 命令**:
```
LW   x3, 0(x1)     # x3 = メモリ[x1+0]  (ワード読み)
SW   x3, 0(x1)     # メモリ[x1+0] = x3  (ワード書き)
LB   x3, 0(x1)     # 1バイトだけ読む (符号拡張)
```

**分岐 (Branch) 命令**:
```
BEQ  x1, x2, label # if (x1 == x2) goto label
BNE  x1, x2, label # if (x1 != x2) goto label
BLT  x1, x2, label # if (x1 <  x2) goto label (符号付き)
```

**ジャンプ命令**:
```
JAL  x1, label      # x1 = PC+4; goto label  (関数呼び出し)
JALR x1, 0(x2)      # x1 = PC+4; goto x2+0   (関数から戻る)
```

**M 拡張 (乗除算)**:
```
MUL  x3, x1, x2    # x3 = x1 * x2  (下位32bit)
DIV  x3, x1, x2    # x3 = x1 / x2  (商)
REM  x3, x1, x2    # x3 = x1 % x2  (余り)
```

### 命令のバイナリ表現 (32bit 固定長)

全命令は 32bit に収まる。フォーマットが 6 種類:

```
R型 (reg-reg):  [funct7 | rs2 | rs1 | funct3 | rd | opcode]
                 7bit    5bit  5bit   3bit    5bit  7bit

  例: ADD x3, x1, x2
  → [0000000 | 00010 | 00001 | 000 | 00011 | 0110011]
       ↑ADD     ↑x2    ↑x1    ↑ADD  ↑x3    ↑ALU-reg

I型 (即値):    [    imm[11:0]  | rs1 | funct3 | rd | opcode]
S型 (Store):   [imm[11:5] | rs2 | rs1 | funct3 | imm[4:0] | opcode]
B型 (Branch):  [imm bits  | rs2 | rs1 | funct3 | imm bits | opcode]
U型 (Upper):   [         imm[31:12]           | rd | opcode]
J型 (Jump):    [         imm bits              | rd | opcode]
```

デコーダの仕事 = この 32bit を解析して「何の命令か」「どのレジスタを使うか」を取り出す。

## 2. パイプライン: 5 段 in-order

### なぜパイプライン?

1 命令を全部やってから次の命令、だと遅い:

```
命令1: [IF][ID][EX][MEM][WB]
命令2:                       [IF][ID][EX][MEM][WB]
→ 10 サイクルで 2 命令
```

パイプライン = 前の命令が次の工程に行ったら、すぐ次の命令を始める:

```
命令1: [IF][ID][EX][MEM][WB]
命令2:     [IF][ID][EX][MEM][WB]
命令3:         [IF][ID][EX][MEM][WB]
→ 7 サイクルで 3 命令 (理想は毎サイクル 1 命令完了)
```

### 5 段の各ステージ

```
IF  命令フェッチ    PC のアドレスで命令メモリから 32bit の命令を読む
    ↓ 命令を次ステージに渡す
ID  デコード        命令を解析: 何の演算? どのレジスタ? 即値は?
                    レジスタファイルから rs1, rs2 の値を読む
    ↓ 演算の種類とデータを渡す
EX  実行            ALU で計算する (足し算、比較、シフト...)
                    分岐命令なら「飛ぶか飛ばないか」をここで判定
    ↓ 計算結果を渡す
MEM メモリアクセス  Load命令: 計算したアドレスでメモリから読む
                    Store命令: メモリに書く
                    それ以外: 素通り
    ↓ 結果を渡す
WB  ライトバック    結果をレジスタファイルの rd に書き込む
```

### パイプラインレジスタ — ステージ間のバケツリレー

各ステージの間に**レジスタ**（データを 1 サイクル溜める箱）を置く:

```
       IF/ID reg        ID/EX reg        EX/MEM reg       MEM/WB reg
         │                 │                │                │
[IF] ──▶ ║ ──▶ [ID] ──▶ ║ ──▶ [EX] ──▶ ║ ──▶ [MEM] ──▶ ║ ──▶ [WB]
         ║                 ║                ║                ║
     pc, instr      rs1_data,rs2    alu_result,        result,
                    imm, ctrl...     mem_data...        rd, ctrl
```

毎クロックで箱の中身が次のステージに流れる。

## 3. 分岐: predict not-taken と 2 サイクルペナルティ

### 問題: 分岐の結果がわかるのは EX ステージ

```
サイクル1: [IF] BEQ x1,x2,label    ← 飛ぶ? まだわからない
サイクル2:     [ID]                [IF] ???    ← 次の命令は何を取る?
サイクル3:         [EX] 判定!      [ID]        [IF] ???
```

`BEQ` が「飛ぶ」か「飛ばない」かは EX ステージの比較が終わるまでわからない。
でもパイプラインは**止まれない** — 毎サイクル次の命令を取りに行く必要がある。

### predict not-taken (飛ばない方に賭ける)

**「きっと飛ばないだろう」** と仮定して、分岐命令の次のアドレス (pc+4) をフェッチ。

**予測が当たった場合** (飛ばなかった): そのまま。ペナルティ 0。

**予測が外れた場合** (飛んだ!):

```
サイクル1: [IF] BEQ
サイクル2:     [ID]       [IF] pc+4  ← 間違い! フラッシュ
サイクル3:         [EX]✓      [XX]       [IF] pc+8  ← 間違い! フラッシュ
サイクル4:                                    [IF] label  ← 正しい命令
```

→ **2 サイクル無駄になる** = 2 サイクルペナルティ

## 4. 除算: 32 サイクル restoring divider

### なぜ除算だけ特別?

足し算・掛け算は 1 サイクルでできる回路がある。
除算は**筆算のように 1 ビットずつ処理**する。32bit / 32bit = **32 ステップ**。

```
筆算の除算:      1 0 1 1  (商)
             ───────────
  10010 │ 11011010
          10010      ← ステップ1: 引けた → 商のビット=1
          ─────
           10010     ← ステップ2: 引けない → 商のビット=0 (復元)
           ...
```

### パイプラインへの影響

DIV が EX にいる 32 サイクルの間、**IF と ID を凍結** (新しい命令を流さない)。
MEM と WB は先行命令を排出 (ドレイン) させる。

## 5. ハザード: パイプラインの「詰まり」問題

### RAW (Read After Write) ハザード

```asm
ADD  x3, x1, x2    # x3 に結果を書く
SUB  x5, x3, x4    # x3 を読みたい! でもまだ WB まで行ってない!
```

```
サイクル3:     [EX]ADD  [ID]SUB ← x3 を読むが、ADD はまだ WB してない!
```

SUB が x3 を読むとき、ADD の結果はまだレジスタに書かれていない。古い値を読んでしまう!

### フォワーディング (バイパス) で解決

結果が**計算された瞬間** (EX の出力) に、待たずに**直接パイプを通して**次の命令に渡す:

```
           ┌──────────────────────────────────────┐
           │            フォワーディング            │
           │  EX/MEM reg の結果 ─────────┐         │
           │  MEM/WB reg の結果 ──────┐  │         │
           │                          ▼  ▼         │
[IF] ──▶ [ID] ──▶ [EX  MUX ← 通常/FWD] ──▶ [MEM] ──▶ [WB]
                    ↑
              rs1,rs2 のデータ選択:
              1. 通常: レジスタから読んだ値
              2. EX→EX FWD: 直前の命令の ALU 結果
              3. MEM→EX FWD: 2つ前の命令の結果
```

フォワーディングの優先順位: EX/MEM (直前の命令) > MEM/WB (2つ前) — より新しいデータが正しい。

### Load-Use ハザード — フォワーディングでも間に合わない唯一のケース

```asm
LW   x3, 0(x1)     # メモリから x3 に読む
ADD  x5, x3, x4    # x3 をすぐ使いたい!
```

LW のデータは MEM ステージの最後まで確定しない。EX→EX フォワーディングでは渡せない。

**解決: 1 サイクルだけ止める (ストール)**

```
検出: ID/EX の命令が Load かつ、その rd が次の命令の rs1 or rs2 と一致

動作:
  ① IF/ID を凍結 (同じ命令をもう 1 回デコード)
  ② PC を凍結 (次の命令を取りに行かない)
  ③ ID/EX にバブル (NOP) を挿入
  → 次のサイクルで MEM→EX フォワーディングが使える
```

## 6. 全体の関係図

```
┌─────────────────────────────────────────────────────────┐
│                    cpu_top                               │
│                                                         │
│  [IF]──▶[ID]──▶[EX]──▶[MEM]──▶[WB]                    │
│   │       │      │       │       │                      │
│   │       │      ├───────┘       │ ← フォワーディング   │
│   │       │      ├───────────────┘   (EX←MEM, EX←WB)   │
│   │       │      │                                      │
│   │       ├──────┤ ← hazard_unit                        │
│   │  ストール/   フラッシュ                               │
│   │  凍結        (分岐ミス時)                            │
│   │                                                     │
│   └──── PC ← 分岐先 / pc+4                              │
│                                                         │
│  命令メモリ (ROM)    データメモリ (RAM)                    │
│  ↑IF が読む          ↑MEM が読み書き                     │
└─────────────────────────────────────────────────────────┘
```

```
ISA (RV32IM) = この CPU が理解できる 55 種類の命令
パイプライン  = 5 段の流れ作業で毎サイクル 1 命令完了 (理想時)
ハザード処理  = 流れが詰まる 3 パターンを検出して回避
  ├── RAW:       フォワーディングで解決 (0 ペナルティ)
  ├── Load-use:  1 サイクルストール + フォワーディング
  └── 分岐ミス:  2 サイクルフラッシュ
```

## 7. RTL モジュール構成 (実装予定)

```
cpu_top.sv
├── if_stage.sv        — PC, 命令メモリ I/F, 次PC選択
├── id_stage.sv        — デコーダ, レジスタファイル, 即値生成
├── ex_stage.sv        — ALU, 分岐判定, 乗算器
├── mem_stage.sv       — データメモリ I/F, Load 拡張
├── wb_stage.sv        — ライトバック MUX
├── hazard_unit.sv     — フォワーディング/ストール/フラッシュ制御
├── divider.sv         — マルチサイクル除算器 (restoring)
├── regfile.sv         — 32×32bit レジスタファイル (2R1W)
└── cpu_pkg.sv         — 定数/型定義
```
