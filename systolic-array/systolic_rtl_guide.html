1. mac.sv — 積和ユニット

設計思想

行列積の最小単位は 「掛けて足す」= MAC (Multiply-ACcumulate)。
これ 1 個で「1 サイクルに 1 回の積和」ができる。16 個並べれば 16 MAC/サイクル。

a (INT8) │ ▼ ┌───────┐ │ × │───▶ prod (INT16: 符号付き乗算) └───────┘ ▲ │ │ ▼ b (INT8) ┌─────────┐ ┌─────────┐ │ + │◀────│ acc │──▶ 出力 (INT32) └─────────┘ │ (レジスタ)│ ▲ └─────────┘ │ ▲ clear?──── 0 ─────┘ (clear=1 なら acc の代わりに 0 を使う)

コード全文と解説

 1module mac #(
 2    parameter int A_W   = 8,    // 入力 a の幅 (INT8 = 8bit 符号付き)
 3    parameter int B_W   = 8,    // 入力 b の幅
 4    parameter int ACC_W = 32    // 累算器の幅 (INT32)
 5)(
 6    input  logic                     clk,
 7    input  logic                     rst_n,   // 非同期リセット (Low active)
 8    input  logic                     en,      // 1 のサイクルだけ積和実行
 9    input  logic                     clear,   // 1 なら acc を 0 にしてから加算
10    input  logic signed [A_W-1:0]    a,
11    input  logic signed [B_W-1:0]    b,
12    output logic signed [ACC_W-1:0]  acc
13);
14    // 符号付き乗算 → 積は A_W + B_W ビット幅
15    logic signed [A_W+B_W-1:0] prod;
16    assign prod = a * b;          // 組合せ回路 (1サイクルで乗算)
17
18    always_ff @(posedge clk or negedge rst_n) begin
19        if (!rst_n)
20            acc <= '0;        // リセット時は 0
21        else if (en)
22            acc <= (clear ? '0 : acc) + ACC_W'(prod);
23    end                           // ↑ prod を ACC_W ビットに符号拡張して加算
24endmodule
ポイント: 22行目の (clear ? '0 : acc) がミソ。 clear=1 なら前の累算値を捨てて 0 + prod、clear=0 なら acc + prod。 これで「新しい計算の開始」と「累積の継続」を 1 行で切り替える。
信号方向意味
en入力1 のサイクルだけ積和実行。0 なら acc は前の値を保持
clear入力新しい行列積の最初のサイクルで 1 にする (累算器リセット)
prod内部a × b の結果。INT8 × INT8 = 16bit 符号付き
acc出力累算結果。INT32 なのでオーバフローの心配なし

2. pe.sv — Processing Element

設計思想

MAC だけでは「計算するだけ」。PE はそれに加えて 隣の PE にデータを渡す 責務を持つ。

  • 活性化 (act): 左から入って、右隣へ 1 サイクル遅延で渡す
  • 重み (w): 上から入って、下隣へ 1 サイクル遅延で渡す
  • 結果 (acc): この PE の中に留まる (= output-stationary)
w_in (上から) │ ▼ act_in ──────┬───▶ MAC ──▶ acc (結果: この PE に蓄積) (左から) │ │ ▲ │ │ │ │ │ w_in │ │ [1clk reg] [1clk reg] │ │ ▼ ▼ act_out w_out (右隣へ) (下隣へ) 重要: MAC は act_in と w_in を直接使う (遅延前の値)。 act_out と w_out は1サイクル後の値 (隣の PE 用)。

コード全文と解説

 1module pe #(
 2    parameter int DW    = 8,     // データ幅 (INT8)
 3    parameter int ACC_W = 32     // 累算器幅 (INT32)
 4)(
 5    input  logic                     clk, rst_n,
 6    input  logic                     compute_en, acc_clear,
 7    // 活性化 (左→右)
 8    input  logic signed [DW-1:0]     act_in,
 9    output logic signed [DW-1:0]     act_out,
10    // 重み (上→下)
11    input  logic signed [DW-1:0]     w_in,
12    output logic signed [DW-1:0]     w_out,
13    // 累算結果
14    output logic signed [ACC_W-1:0]  acc
15);
16    // ── パススルーレジスタ ──
17    // データを「次のサイクルで隣へ渡す」ための 1段レジスタ。
18    // これが systolic (心拍的) な 1clk 遅延の正体。
19    always_ff @(posedge clk or negedge rst_n) begin
20        if (!rst_n) begin
21            act_out <= '0;
22            w_out   <= '0;
23        end else begin
24            act_out <= act_in;   // 今の入力を次のサイクルで右へ
25            w_out   <= w_in;     // 今の入力を次のサイクルで下へ
26        end
27    end
28
29    // ── MAC インスタンス ──
30    // act_in × w_in を毎サイクル累算。
31    // MAC の a = act_in (遅延前)、b = w_in (遅延前) を直接接続。
32    mac #(.A_W(DW), .B_W(DW), .ACC_W(ACC_W)) u_mac (
33        .clk(clk), .rst_n(rst_n),
34        .en(compute_en), .clear(acc_clear),
35        .a(act_in),  .b(w_in),  .acc(acc)
36    );
37endmodule
なぜ act_in を直接 MAC に繋ぐか: act_out は act_in の 1 サイクル遅延コピー。MAC が act_out を使うと 「1 サイクル前のデータ」で計算してしまい、タイミングがずれる。 同じサイクルの act_in と w_in で掛けることで、 スキューバッファが作った「同時到着」が正しく反映される。

3. skew_buffer.sv — スキューバッファ

設計思想

シストリックアレイでは、全データを同時に投入すると PE(0,0) だけが正しいタイミングで受け取り、 他の PE はずれる。事前にずらして投入することで、各 PE に正しいペアが同時到着する。

入力 data_in[0..3] に毎サイクル新しいデータが来る。 スキューバッファが各行をずらして出力する: data_in[0] ─────────────────────▶ data_out[0] 遅延 0 (パススルー) data_in[1] ──▶ [SR] ─────────────▶ data_out[1] 遅延 1 data_in[2] ──▶ [SR]──▶[SR] ──────▶ data_out[2] 遅延 2 data_in[3] ──▶ [SR]──▶[SR]──▶[SR]▶ data_out[3] 遅延 3 SR = シフトレジスタ (1サイクル遅延の FF)

なぜずらすのか — 具体例

4×4 の行列積 C = A × W を計算するとき:

  • 活性化スキュー: 行 0 は遅延 0、行 1 は遅延 1、…行 3 は遅延 3
  • 重みスキュー: 列 0 は遅延 0、列 1 は遅延 1、…列 3 は遅延 3

こうすると PE(r,c) に A[r][k] と W[k][c] が同じサイクル T = k + r + c で到着する。

例: サイクル T=0 に投入するデータ 活性化 (行スキュー後): 重み (列スキュー後): 行0: A[0][0] ← 遅延0で即到着 列0: W[0][0] ← 遅延0で即到着 行1: (まだ) ← 遅延1で次サイクル 列1: (まだ) ← 遅延1で次サイクル 行2: (まだ) ← 遅延2 列2: (まだ) ← 遅延2 行3: (まだ) ← 遅延3 列3: (まだ) ← 遅延3 → T=0 では PE(0,0) だけが有効データを受け取る。 T=1 では PE(0,1) と PE(1,0) が受け取る。 … 対角線上に波紋が広がるように計算が進む。

コード全文と解説

 1module skew_buffer #(
 2    parameter int N  = 4,    // 行(列)数
 3    parameter int DW = 8     // データ幅
 4)(
 5    input  logic                    clk, rst_n,
 6    input  logic signed [DW-1:0]   data_in  [N],
 7    output logic signed [DW-1:0]   data_out [N]
 8);
 9    // ── 行0: 遅延0 (そのまま通す) ──
10    assign data_out[0] = data_in[0];
11
12    // ── 行1: 遅延1 (FF 1段) ──
13    logic signed [DW-1:0] sr1;
14    always_ff @(posedge clk or negedge rst_n) begin
15        if (!rst_n) sr1 <= '0;
16        else        sr1 <= data_in[1];
17    end
18    assign data_out[1] = sr1;
19
20    // ── 行2: 遅延2 (FF 2段) ──
21    logic signed [DW-1:0] sr2 [2];
22    always_ff @(posedge clk or negedge rst_n) begin
23        if (!rst_n) begin
24            sr2[0] <= '0;  sr2[1] <= '0;
25        end else begin
26            sr2[0] <= data_in[2];   // 入力 → 1段目
27            sr2[1] <= sr2[0];       // 1段目 → 2段目(出力)
28        end
29    end
30    assign data_out[2] = sr2[1];
31
32    // ── 行3: 遅延3 (FF 3段) ──
33    logic signed [DW-1:0] sr3 [3];
34    always_ff @(posedge clk or negedge rst_n) begin
35        if (!rst_n) begin
36            sr3[0] <= '0;  sr3[1] <= '0;  sr3[2] <= '0;
37        end else begin
38            sr3[0] <= data_in[3];   // 入力 → 1段目
39            sr3[1] <= sr3[0];       // 1段目 → 2段目
40            sr3[2] <= sr3[1];       // 2段目 → 3段目(出力)
41        end
42    end
43    assign data_out[3] = sr3[2];
44endmodule
シフトレジスタの直感: sr3 の 3 段は「バケツリレー」。毎サイクル中身が 1 段ずつ移動する。 入力されたデータは 3 サイクル後にようやく出力に現れる。

4. systolic_4x4.sv — アレイ本体

設計思想

このモジュールが解決する問題は 3 つ:

  1. 重みの保管と供給 — 重みバッファに事前格納し、計算時に 1 行/サイクルでストリーム
  2. スキューの生成 — 活性化 (行) と 重み (列) の両方にスキューバッファを配置
  3. PE の接続 — 4×4 グリッドで横と縦のワイヤを正しく配線
┌────────────────────────────────────────────┐ │ systolic_4x4 の内部構造 │ │ │ │ ┌──────────────┐ ┌──────────────┐ │ │ │ w_buf[4][4] │ │ w_cnt │ │ │ │ 重みバッファ │───▶│ ストリーム │ │ │ │ (weight_load │ │ カウンタ │ │ │ │ で事前格納) │ │ (0→1→2→3→停止)│ │ │ └──────────────┘ └──────┬───────┘ │ │ │ w_stream[c] │ │ ▼ │ │ ┌──────────────┐ │ act_in[r] ──┤──▶ ┌───────────┐ │ 列スキュー │ │ │ │ 行スキュー │ │ col c を │ │ │ │ row r を │ │ c cyc 遅延 │ │ │ │ r cyc 遅延│ └──────┬───────┘ │ │ └─────┬─────┘ │ w_skewed[c] │ │ │ act_skewed[r] │ │ │ ▼ ▼ │ │ ┌─────────────────────────────┐ │ │ │ 4×4 PE グリッド │ │ │ │ act: 左→右 w: 上→下 │ │ │ │ result[r][c] = PE(r,c).acc │ │ │ └─────────────────────────────┘ │ └────────────────────────────────────────────┘

コードの重要部分 — 3つのブロック

① 重みバッファと重みストリーミング

// ── 重みバッファ: weight_load で1要素ずつ書き込み ──
logic signed [DW-1:0] w_buf [N][N];
always_ff @(posedge clk) begin
    if (weight_load)
        w_buf[weight_row][weight_col] <= weight_data;
end

// ── ストリームカウンタ: 計算中に 0→1→2→3 と進み、1行/cyc 出力 ──
logic [$clog2(N+1)-1:0] w_cnt;
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)       w_cnt <= '0;
    else if (acc_clear) w_cnt <= '0;           // 新しい計算の開始
    else if (compute_en && w_cnt < N)
                      w_cnt <= w_cnt + 1;   // N行出したら停止
end

// ── w_stream: w_buf の w_cnt 行目を列ごとに出力 ──
assign w_stream[c] = (compute_en && !acc_clear && w_cnt < N)
                   ? w_buf[w_cnt][c] : '0;
!acc_clear ガード: acc_clear サイクルでは活性化が 0 なので積も 0 だが、 重みストリームを止めておくことで列スキューバッファに余計な値が入るのを防ぐ。

② スキューバッファ ×2

// 活性化: 行 r を r サイクル遅延
skew_buffer u_act_skew (.data_in(act_in),  .data_out(act_skewed));

// 重み: 列 c を c サイクル遅延
skew_buffer u_w_skew   (.data_in(w_stream), .data_out(w_skewed));

同じ skew_buffer モジュールを 2 回使う。 活性化には「行スキュー」、重みには「列スキュー」として機能する。

③ PE グリッドの接続

// 水平ワイヤ: act_h[r][0] = スキュー出力、act_h[r][c+1] = PE(r,c).act_out
logic signed [DW-1:0] act_h [N][N+1];
// 垂直ワイヤ: w_v[0][c] = スキュー出力、w_v[r+1][c] = PE(r,c).w_out
logic signed [DW-1:0] w_v   [N+1][N];

for (c = 0; c < N; c++)
    assign w_v[0][c] = w_skewed[c];     // 列 c の上端に重みを注入

for (r = 0; r < N; r++) begin
    assign act_h[r][0] = act_skewed[r]; // 行 r の左端に活性化を注入

    for (c = 0; c < N; c++) begin
        pe u_pe (
            .act_in  (act_h[r][c]),      // ← 左から
            .act_out (act_h[r][c+1]),    // → 右へ
            .w_in    (w_v[r][c]),        // ↑ 上から
            .w_out   (w_v[r+1][c]),      // ↓ 下へ
            .acc     (result[r][c])      // ■ 結果
        );
    end
end
配線の図解 (act_h と w_v): w_v[0][0] w_v[0][1] w_v[0][2] w_v[0][3] │ │ │ │ ▼ ▼ ▼ ▼ act_h ──▶[PE00]──▶[PE01]──▶[PE02]──▶[PE03]──▶ (未使用) [r=0] │ │ │ │ ▼ ▼ ▼ ▼ act_h ──▶[PE10]──▶[PE11]──▶[PE12]──▶[PE13]──▶ [r=1] │ │ │ │ ▼ ▼ ▼ ▼ act_h ──▶[PE20]──▶[PE21]──▶[PE22]──▶[PE23]──▶ [r=2] │ │ │ │ ▼ ▼ ▼ ▼ act_h ──▶[PE30]──▶[PE31]──▶[PE32]──▶[PE33]──▶ [r=3] │ │ │ │ ▼ ▼ ▼ ▼ (未使用) (未使用) (未使用) (未使用) ──▶ = act_h[r][c] → PE → act_h[r][c+1] (水平) │▼ = w_v[r][c] → PE → w_v[r+1][c] (垂直)

5. なぜ output-stationary か

最初に試した weight-stationary (失敗した設計)

❌ weight-stationary (横方向のみ): PE(r,c) に W[r][c] を固定。活性化 A[r][k] が横に流れる。 PE(r,c).acc = W[r][c] × (A[r][0] + A[r][1] + A[r][2] + A[r][3]) = W[r][c] × Σ_k A[r][k] これは行列積ではない！ 毎サイクル同じ重み W[r][c] で掛けているので、 K 個の積の「和」ではなく「同じ重みで K 回掛けた和」になる。

正しい行列積に必要なこと

✓ 正しい行列積: C[r][c] = A[r][0]×W[0][c] + A[r][1]×W[1][c] + A[r][2]×W[2][c] + A[r][3]×W[3][c] 各項で k が変わるごとに異なる重み W[k][c] が必要。 → 重みを固定(stationary)するのではなく、毎サイクル流す必要がある。

output-stationary の解決策

output-stationary: - 活性化: 左→右に流れる (PE ごとに 1cyc 遅延) - 重み: 上→下に流れる (PE ごとに 1cyc 遅延) ← これが追加 - 結果: PE に留まる (= output が stationary) PE(r,c) は毎サイクル異なる重みを受け取る: T=k+r+c: act=A[r][k], w=W[k][c] → 積 = A[r][k]×W[k][c] K サイクルで K 個の異なる積が累算され: acc = Σ_k A[r][k]×W[k][c] = C[r][c] ✓

6. タイミングアニメーション

各 PE がどのサイクルで何を計算するかを可視化。 k0〜k3 は A[r][k]×W[k][c] の k 番目の積和を表す。

T = 0
